Merit Order is a self-hosted LLM gateway. Its job is to lower LLM spend for day-to-day use (coding agents such as pi and Claude Code, internal apps, SDKs) without users changing how they work.

Pre-production: version 0.0.1. Most of Merit Order is tested only against mocks of each provider's API, written from the provider's docs. What has been checked live, and what hasn't, is in What's verified below: OpenRouter, Anthropic and OpenAI, Claude Code sessions, the Docker Compose stack, GPUs on a local kind cluster and one SkyPilot replica on a Lambda GPU have been; the other providers, the rest of the GPU cycle on real clouds, Entra and Google sign-in, batch APIs and bills have not. Version 0.1.0 comes once the checks in the right-hand column pass (ROADMAP.md).

The name comes from power grids. Operators dispatch generators in merit order: the cheapest marginal cost first, with expensive "peaker" plants switched on only when demand needs them. Merit Order does the same with tokens. When steady load justifies it, your own GPUs become the cheap baseload. API endpoints are always available as the peakers that cover spikes and everything else. The router sends every session to the cheapest capacity that meets its quality bar.

It does three things:

  1. Routes each session to the cheapest model and backend that meets the task's quality bar.
  2. Runs open-weight models on your own GPUs (SkyPilot, Kubernetes, or servers you run) when sustained load makes that cheaper than paying per token, and turns them off when it doesn't. API endpoints (Bedrock, Vertex AI, Foundry, ...) are always on, as the fallback and the overflow.
  3. Saves tokens with provider prompt caching, cache-aware routing, careful compression and batch prices.

Around that: sign-in (Entra, Google Workspace, generic OIDC, SCIM), budgets and hard safeguards, a savings ledger that shows what every request would have cost without the gateway, and a web console to watch and control all of it: spend, savings, where every GPU runs and what it costs, and the switches to stop it.

Six ideas behind the design

  1. Marginal cost, not list price. A GPU that is already running is a sunk cost for that hour, so its spare capacity is close to free. Use it, even for a better model than the task needs.
  2. Moving a session costs money. Prompt caches live on the backend. Switching backends means paying again for the whole context, so the router counts that before moving anything.
  3. The harness owns the conversation. By default the gateway stores routing metadata (hashes, timestamps, which backend), never conversation content. The exceptions are opt-in or explicit: the response cache, the Responses API's stored mode, and batch files held (sealed) until a provider or GPU takes them.
  4. APIs are the floor, GPUs are an optimization. Every model that runs on your GPUs should also have an API route, so GPUs never become a single point of failure. The console warns about any model that doesn't before anyone stops its GPUs.
  5. Clone and run. docker compose up gives you a working gateway: on mock backends with no keys, on real ones with a single key. GPUs, sign-in and Kubernetes are opt-in layers.
  6. Every cost is visible next to the switch that controls it. Anything that spends money (a team, a GPU, the whole organization) shows what it costs and can be capped or stopped from the console.

Glossary

Term Meaning
Harness The client driving the model: pi, Claude Code, Cursor, an SDK app
Session One conversation or agent run; the unit of stickiness and caching
Backend A configured place models run: anthropic, bedrock, openrouter, or your own GPUs (gpu-qwen-coder)
Route One model on one backend, with its price; a model can have several
Level What a request sent with model: "auto" needs, per kind of work, 1 to 5 (coding:3); set from its wording and tools, never its length. Also called the quality floor (X-Route-Floor)
Score A model's quality for a kind of work, 1 to 5, from published benchmarks (Epoch AI by default) or measured with meritorder eval
Headroom Spare capacity on a running GPU replica before it misses its latency target
Shadow price The internal price for self-hosted tokens: about 0 when idle, rising toward the API price as the replica fills
Rebuild cost The cost to process a session's context again on a backend whose cache is cold
Counterfactual cost What a request would have cost on the baseline model (baseline_model, set for the organization or a team) at its API price
Ledger One row per request: who, which model and backend, tokens, cost, counterfactual cost and savings by cause; never content
